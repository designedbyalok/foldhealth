## Everything they share

<Steps>
  <Step title="Member cell: identical on every list">
    Name (button → Quick View), `(gender • age)` + DOB tooltip, FoldID tag, preferred-language badge. Click anywhere on the row to open the Quick View.
  </Step>
  <Step title="FilterChip filter language">
    Every filter is `Label ⌄` when empty, `Label : Value ✕` when active. Multi-select where the data allows. Never a plain `<select>`.
  </Step>
  <Step title="Bulk bar via checkbox column">
    Select rows and the **BulkBar** appears with actions scoped to the worklist (assign, change status, add to campaign, export).
  </Step>
  <Step title="Deep-linkable state">
    Filters, sort, page, and open drawer all serialize into the URL hash, send a link and the recipient lands where you are.
  </Step>
  <Step title="Live counts">
    The count next to each worklist name in the SubNav updates as the underlying data changes.
  </Step>
</Steps>

## Assignment and roles

Every worklist has an **Assignee** column with a role-aware picker. The picker respects role scoping, HCC has multiple roles (Support, Coder, Reviewer 1, Reviewer 2/QA, Compliance); TCM/TOC/CCM/HEDIS use a single Care Manager role.

Bulk **Change Assignee** on any list skips rows already completed for that role and prompts before overwriting an existing assignment.

## Which list should I use?

- Need a workflow **now**? Start on the list that names your task (TCM for a discharge, TOC for the agent queue, HCC for coding).
- Need to see **all patients across programs**? Use [All Patients](/features/all-patients).
- Need to build a **reusable cohort** and act on it? Use [Population Groups](/features/population-groups).
