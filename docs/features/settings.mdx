## Agents

The Agents tab is a table of every AI agent in your org with: name, use case, version, voice configuration, last update, and status.

- **Row click**: opens the [Agent Builder](/features/agent-builder).
- **Call Queue**: opens the Call Queue drawer for the agent (Ongoing / In Queue / Log).
- **Call Analytics**: jumps to the agent's slice of the AI Analytics dashboard.
- **⋯ menu**: Duplicate, Delete, Audit Log.

### Walkthrough: configure a new agent end-to-end

<Steps>
  <Step title="Create the agent">
    In Settings → Agents click **+ New Agent**. Name it, pick a use case template, and click **Create**. It opens straight into the Agent Builder.
  </Step>
  <Step title="Design the flow">
    Follow the [Agent Builder walkthrough](/features/agent-builder). Save often, Publish when ready.
  </Step>
  <Step title="Attach goals">
    Back in Settings, open **Goals**. Click **+ New Goal** and follow the 4-step **Goal Wizard**: choose category (TCM, Outreach, Onboarding, Preventive, Billing), set targets and weights, pick completion criteria, and attach it to your agent.
  </Step>
  <Step title="Fill the knowledge base">
    Open **Knowledge Base**. Add question/answer pairs the agent should reference during conversations. Group them by topic for faster retrieval.
  </Step>
  <Step title="Set escalation rules">
    Open **Compliance Policies**. Define what triggers a transfer to a live human, patient distress, explicit request, PHI concern, unresolved intent after N turns.
  </Step>
  <Step title="Assign to a worklist">
    Go to the appropriate worklist (TOC, HEDIS, etc.). In the row's **Agent Assigned** column, pick your new agent. It's now live.
  </Step>
</Steps>

## Content

- **Emails**: the shared email library. Every campaign email lives here; edit inline or open the [Email Builder](/features/campaigns).
- **Forms**: the shared form library. See the [Forms doc](/features/forms) for the full builder walkthrough.

## Embedded Components

For teams embedding Fold surfaces inside another EHR or portal.

- **Domain Registry**: whitelist domains that can iFrame Fold. Each row shows HIPAA-compliance status and a per-domain audit log.
- **Component Library**: configure which components are embeddable (Prior Auth, Risk Dashboard, HEDIS Tracker, more). Each component has a 4-step wizard: **Identity → Surfaces → Context → Preview**. Surfaces pick where it renders (Fold Web, Sidecar, Mobile); Context defines the JWT payload the host must sign.
- **Audit Log**: timeline of every allowlist / component change, grouped by month with color-coded action types.

## Messages

Chat groups (patient ↔ care team threads) are configured here.

- **Chat Groups**: each group has a routing rule (which agents can respond, on what intents) and optional business hours.
- **Business Hours**: off-hours coverage: fallback message, escalation to on-call, or handoff to an agent.
- **Agent Rules**: per-group conditional rules that override the default routing.

## Account, Billing, Member Leads

- **Account → Users**: the user table, invite flow (single-email confirmation), and role assignment.
- **Billing**: plan, monthly usage, invoices.
- **Member Leads → Care Team**: the roster used for pre-enrollment outreach and lead assignment.

## Audit Log

Every Settings change is audit-logged. Open the **Audit Log** on any tab (or the org-wide one from the ⋯ menu) to see a timeline of Create / Update / Delete events, filterable by user, entity type, and date range.
