**Population** is the workspace care managers spend most of their day in. It's a three-pane layout: the left **Sidebar** (app-level nav), a middle **SubNav** rail listing the worklists, and the main content area that shows the active worklist, patient profile, or population group.

## Choosing the right list

<Steps>
  <Step title="Are you doing post-discharge follow-up?">
    Open [TCM Worklist](/features/tcm-worklist) for the care-manager queue, or [TOC](/features/toc-worklist) to monitor agent-led outreach. Patients are grouped by outreach window (48h, 7d) and lifecycle stage.
  </Step>
  <Step title="Are you coding for risk adjustment?">
    Open [HCC Worklist](/features/hcc-worklist). Rows are members with open ICD gaps; workflow moves through Support → Coder → QA → Compliance.
  </Step>
  <Step title="Are you closing quality gaps?">
    Open [HEDIS Worklist](/features/hedis-worklist). Rows are care gaps grouped by measure (e.g. BCS, COL, CDC).
  </Step>
  <Step title="Are you running chronic-care management?">
    Open [CCM Worklist](/features/ccm-worklist). Includes time-tracking, billing review, and monthly close.
  </Step>
  <Step title="Are you scheduling Annual Wellness Visits?">
    Open [AWV Worklist](/features/awv-worklist). Rows are members due for AWV with Provider and Location filter chips.
  </Step>
  <Step title="Do you need everything at once?">
    Open [All Patients](/features/all-patients). It dedupes patients across every worklist by normalized member ID.
  </Step>
</Steps>

## Shared table mechanics

Every worklist shares the same primitives so the mental model transfers list-to-list:

- **Member cell**: Name (linked to Quick View), (gender • age), DOB tooltip, FoldID tag, preferred-language badge.
- **Row click**: opens the **Quick View** drawer with a compact patient summary.
- **Filter chips**: every filter is a `FilterChip` (`Label ⌄` → `Label : Value ✕`). Never a plain select.
- **Bulk actions**: checkbox selection surfaces the **BulkBar** with actions relevant to the list.
- **Search**: matches name, member ID, and initials.
- **Deep links**: every table state (filters, sort, pagination, selected patient) is in the URL hash.

## Agent Queue

Inside worklists that use AI agents (TOC especially), the **Agent Queue** tab shows patients currently assigned to an agent with a **KPI summary bar** (calls placed, connect rate, transfer rate, average handle time) and per-agent status. See [Calls → Call Queue Drawer](/features/calls) for live monitoring.

## Layout details

- **SubNav is 200px**: collapse it via the ⇤ handle to reclaim horizontal space on narrow tables.
- **Worklist order is user-customizable**: drag list items in the SubNav to reorder; the order persists per user.
- **Counts update live**: worklist row counts refresh on every fetch; no page reload needed.
