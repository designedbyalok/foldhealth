# P360 (Patient 360): Complete Context

Single reference for everything that makes up the P360 patient profile: routing,
UI structure, data layer, Supabase schema, seeds, docs, history and known gaps.
All `src/` paths are relative to the repo root. "store" means
`src/store/useAppStore.js`.

Last compiled: 2026-09-30.

---

## 1. What P360 is

One profile per member that follows them across every worklist ("One patient,
one story", `PRODUCT.md`). It combines clinical history (PAMI/Hx), care programs,
care plans, outreach, tasks, gaps, vitals, notes and monitoring on a single page.

- Identity is the **Fold ID** (`member_id`). Since #372, `patients.id = member_id`
  and every worklist table was re-keyed to it.
- The main profile table is `public.p360_profiles`, keyed by `patient_id`
  (unique upsert target).
- `patients` (the "Central Profile") is the source of truth for basic
  demographics (#375).

## 2. Routing and entry points

### Mounting

- `src/layouts/AppLayout.jsx:39` lazy-loads `PatientDetailView`.
- In `PopulationView` (`AppLayout.jsx:127-139`), a truthy `selectedPatientId`
  replaces the page with TopBar + `<PatientDetailView/>` + `<CallPopoverHost/>`.
- Global drawers mounted in AppLayout (`AppLayout.jsx:577-587`):
  `EditPatientDrawer` (invite mode and edit mode) and `QuickViewDrawer`.

### Hash routes (`src/lib/router.js`)

| Format | Notes |
|---|---|
| `#/population/<listSlug>/patient/<memberId>[/<tab>[/<cm-subtab>[/<program>[/<step>]]]]` | Current format (L555-563) |
| `#/hedis/patient/<memberId>/...` | HEDIS bucket, also used as a generic P360 link by `PatientBanner` |
| `#/population/patient/<id>/...` | Legacy, still parsed (L537-541) |

- `stateToHash` prefers memberId via `findPatientMemberId` across
  `PATIENT_SLICES` (L36).
- Tab slugs derive from `PROFILE_TABS`; Overview writes no segment.
- Care Management sub-tab slugs: `care-programs`, `comprehensive-care-plan`,
  `program-activity-log`. Legacy `care-programs` tab slug and `.../summary` map
  to the new structure (L52-79).

### Store navigation actions (store L727-813)

- `navigateToPatient(patientId, { profileTab, programCode })`: sets
  `selectedPatientId`, resets program/step. `'Care Programs'` maps to
  `patientProfileTab: 'Care Management'` + `careManagementTab: 'Care Programs'`.
  `programCode` sets `pendingCareProgramCode`. Forces `activePage: 'population'`.
- `navigateBackToWorklist`, `setPatientProfileTab`, `setCareManagementTab`,
  `openCareProgram(programKey)`, `closeCareProgram`, `setCareProgramStep`,
  `setCarePlanSummaryOpen`, `clearPendingCareProgramCode`.

## 3. Page shell: `PatientDetailView`

`src/features/patient/PatientDetailView.jsx`. No props; everything is store-driven.

- **Patient resolution (L194-201):** matches `id` OR `memberId` across
  `patients` → hcc → awv → ccm → snp → hedis → allPatients. Non-`patients` rows
  go through `worklistMemberToPatient()` (L49-68) to normalise field shapes.
- **Cold refresh (L245-267):** fetches empty slices; if the id still doesn't
  resolve, calls `navigateBackToWorklist()` (no "not found" screen). Deep-link
  memberIds are rewritten to the store row id.
- **Left panel:** width default 496, drag range 300-700; collapse state in
  localStorage `patientLeftPanelCollapsed:<userId>`; 320 ms unmount delay.
  When collapsed, left tabs move into the right tab bar as `extraTabs`.
- **Layout:** `CcmTimerDockProvider` > `PatientP360Banner` + `CcmTimerWidget` >
  left `PatientProfileTabs` | right `ProfileTabBar` + tab content >
  `P360NotePreviewMount` (note preview / edit drawers).

## 11. Known gaps and gotchas

1. **Insurance edits are not saved.** `EditPatientDrawer` reads `insurance_*`/`ph_*`
   into the form, but the `updateP360Profile` payload (L265-297) omits them.
2. **Removed medications stay visible.** `removePatientMedication` (store L488)
   deletes then calls `fetchPatientMedications`, which returns early because of
   its loaded guard; the row isn't removed from state until reload.
   `deletePatientMedication` (Med Rec) removes optimistically.
3. **JSA-only ids don't resolve** in `PatientDetailView` (router's
   `PATIENT_SLICES` includes `jsaMembers`; the view lookup does not).
4. **CCM missing from `CARE_PROGRAM_CATALOG`**, so the CCM worklist's
   `programCode:'CCM'` only opens an existing enrollment.
5. **DOB source differs**: EditPatientDrawer pre-fills from the patient row;
   banner/ProfileTab prefer `p360_profiles.date_of_birth`.
6. **Id aliasing**: a patient may appear as `p8`, `ap-011`, `snpw-001` or a Fold
   ID. `clinical_notes.patient_id` has no FK, so notes are fetched under every alias.
7. **`p360Loading` is global** while `p360ProfilesById` is per patient.
8. **Stale comments**: store L360-361 (problems mock fallback) and L1221-1225
   (`programsForPatient` fallback) describe behaviour that no longer exists;
   `programsForPatient` is never called.
9. **Placeholders**: 4 right-panel tabs, banner More items, Medical History add,
   Lab/Imaging add, Family History add, care-note composer, hard-coded Diagnosis
   Gaps DOS, local-only tag removal.
10. **TopBar comment is outdated**: it says `all_patients` rows have no profile
    view, but `PatientDetailView` resolves them and TodayView navigates to them.
11. **`org_settings` is keyed by `user_id`**, not org.
12. **Schema tolerance**: problems retry without `note` if the column is missing;
    step status is session-only if its table is missing.
